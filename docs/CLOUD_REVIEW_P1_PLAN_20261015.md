# Replay 2.0 P1 任务契约

模式：实现 → 隔离验收 → 独立只读审查 → 发布 Draft PR。

## 目标与基线

基于 PR #6 的固定提交 `51d6b8bb96e3a935aafca1e281af86e05fc5afa5`，增量实现真实 GitHub 受限发布，并拆开重要程度和判断置信度。保留现有界面结构、原比赛上传器、来源绑定及完整 Git 历史安全校验。本机外层维护仓库的未提交工作不纳入本分支。

先回答两项独立问题，再记录网络与实机证据：连接器是否满足提交身份/CAS；关键但不确定的决策怎样表达。随后按真实 GitHub 隔离仓库、807 动作本地性能、原数据完整性、最终回归组织报告。

## 当前核查与最小方案

- 连接器 create_commit 的公开参数没有 author/committer，不能凭 expected_sha 推断双身份合规。受限写入器应显式设置两种专用 noreply 身份，并核对 GitHub 返回的原始提交对象。
- GitHub 在线 GraphQL schema 的 RefUpdate 包含 beforeOid（更新前必须指向的值）和 force。拟组合 REST 创建单父/单文件提交与 GraphQL updateRefs 的 beforeOid、force=false；不以 REST 快进检查冒充精确 CAS。
- 复盘增加兼容的新版语义：重要程度决定关注顺序，置信度独立显示；建议/疑似问题/正向评价独立表达，不因“未经规则引擎证明”统一降为蓝色，也不提供无证据的“确定错误”标签。现有 V1 报告只做保守展示适配，不改写远端历史文件。
- 对首次云端同步测量 CPU、RSS、事件循环和 UI；沿用现有 worker 基础分离重计算，只有测量或审查证据要求时才改动相关路径。

## 授权与禁止

允许在新建私有 GitHub 隔离仓库写入合成比赛与复盘，完成创建/读取/CAS 冲突/回执/上传共存实验。隔离仓库不上传任何真实回放或 Coach Notes。真实 807 动作仅用本机只读副本和临时本地仓库验收。

不合并旧 PR、不替换桌面、不改名、不写真实数据仓库、不改真实历史比赛/Notes/收藏、不调用收费模型、不安装后台任务。真实数据仓库单场发布仍需用户另行明确批准。凭据只由现有受信任 GitHub 身份提供，不写入源码、报告、日志或 UI。

## 完成条件

1. 受限适配器覆盖私有目标/固定仓库分支/精确路径/单父/单文件/双身份/完整历史验证、预期 blob/head、原子 CAS、冲突及回执验证；不自动 rebase、force 或覆盖他人。
2. 真实 GitHub 隔离实验成功，网络回执与独立读取可核对；失败和未验证项如实记录。
3. 新旧报告语义测试和 UI 验收能区分重要程度、置信度、判断性质；保持旧界面及定位功能。
4. 807 动作首次同步有 CPU/内存/响应指标；远端源改变后旧标记失效；原比赛上传器共存。
5. 原 161 场比赛和 Coach Notes 前后只读逻辑行哈希核对；完整回归、发布扫描、独立审查和中文报告后创建独立 Draft PR。

风险：连接器权限与 CLI 登录范围不同；仓库 Contents 权限不是目录 ACL；断网回执不确定、重计算内存峰值、第三方分支历史都可能使发布或同步失败关闭。保留原版本和原历史，不通过放宽验证解决。
