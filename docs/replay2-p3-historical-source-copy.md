# P3 历史发布源的隔离兼容副本

当本地机器名称或批次级事件序号与历史已发布源不同，现有云端 reader 必须继续返回 `stale`。不能仅依据动作数、局数或锚点相同放行，也不能修改报告绑定的源哈希。

`src/review/historical-replay-copy.mjs` 提供显式准备函数 `prepareHistoricalReplayCopy`，用于受控的独立副本验收；它没有加入默认 reader、导入器、上传器或桌面启动链路，没有数据库、文件系统或网络写入。

调用方必须先通过原有 Git 私有性、完整历史扫描、manifest/parts/hash、源重建与报告绑定检查，取得不可伪造的 verified source 对象。函数先完整构建原始本地数据；隐私或安全异常直接失败。仅在内容哈希不同时，复制数据并尝试以下有界兼容：

- 卡名仅能在明确卡槽、既存可见对象和精确 Arena ID 上，按调用方显式审查过的中英文别名恢复。英文来自已验证发布源的字典；别名不由报告或浏览器提供。能力还要求相同可见来源与固定后缀。
- 忠诚指示物兼容限 type 7 的精确 `忠诚` → `Loyalty` 标签；数量和其他属性不变。
- 序号只处理 steps/turns 的事件，逐锚点比较源序号；所有出现的偏移必须是同一个安全整数，不补缺失序号、不重排事件。
- 使用原 builder 重新计算描述、上下文、全部局面与分片；完整内容哈希必须精确等于历史源。任何其他差异均拒绝。

返回独立 replay 与来源收据，原数据不变。调用方应保持原副本与结果分开，记录精确输入指纹、别名来源、原始/发布哈希与远端 revision。历史副本必须交给未修改的 reader 再次验证，不能用准备函数的返回值作为 ready 标记。

本功能不自动修复现有桌面库，也不解决未来导入的全局序号或被汉化的 enUS 资源。正式接入前仍需明确历史版本保存和稳定机器身份策略；本阶段不做迁移或部署。

验证：`node --test tests/historical-replay-copy.test.mjs`；再运行云端 reader/compute/sync、隐私、历史和 Viewer 回归。真实报告写入、真实 GitHub 读取、隔离 UI 与正式桌面验收分别记录，不混称端到端完成。
