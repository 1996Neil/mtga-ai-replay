# 全系统轻量运行约束

2026-10-31。目标是减少工作本身：空闲不读历史，不变不重建，只对变化记录
执行必要的解析、关联和发布校验。不能仅把全量工作移到另一个进程就声称增量。

正常路径：

- 日志：已有字节游标，仅解析追加内容；多场更新共享一次上下文读取。
- 页面：只轮询小版本号，历史目录、账号、轮抽与当前回放仅在对应版本变化时读取。
- 关联：复用已核验且源版本、远端对象、规则都未变的记录；只重新核对变化的比赛。
- 上传：无变化不启动 Git 或网络；变化时只写、校验和回读本次新增／修改的对象。
- 缓存：按版本失效、合并并发请求，不增加常驻轮询和依赖。
- 收藏：当前游戏 API 只能读取整份收藏；只在明确更新时读取，两次稳定性确认保留。
  这不属于后台历史扫描。

首次建索引、损坏数据修复、显式审计可以单独处理历史，但不得默默成为日常路径。
必要的账号归属、来源版本和原子写入仍保留。

完成条件：无变化时重读取／重计算计数为零；单条变更只影响对应记录；
重试不重复生成或上传；账号隔离与数据完整性回归通过。改动与证据在完成后补录。

## 本次收敛

- 仓库 `AGENTS.md` 加入运行成本约束，覆盖后续新功能；未引入依赖、常驻线程或新定时任务。
- 网页每 5 秒取小版本号，目录、账号与轮抽只在各自版本变化时请求。服务端单结果缓存合并
  并发，变化中的加载重试一次，持续变化时让下一次正常轮询重试，不错误标记已消费。
- 账号查询仅读账号与活动账号元数据，不解码观察正文。轮抽已发布清单优先展示，
  旧赛事重建只作无发布记录时的兼容，不变牌组与牌池投影复用。
- 采集器无新日志时只查文件版本，不再启动 Python。无变化不写 sources/meta；
  SQL 观察修订计数区分纯追加与数据修正，纯追加只读 `seq > 游标`。
- 不变的 100 条观察分片与解析结果复用；变化只重建尾分片。解析缓存限 4 MB、
  128 项且结果冻结；单目录观察缓存最多 4 处，单牌名映射投影缓存最多 128 段。
- 增量对局重建只查询变化比赛的摘要，并在同一次任务内只解码一份共享上下文。
- 关联证据复用紧凑主牌组与内容版本／Git 对象 ID，不重复读取不变回放或重新规范化。
  仅改变的本地版本、远端对象或规则触发再次核对；持久证明缓存最多 512 项。
- 自动上传的输入与最终发布文件未变时，在 Git／网络／观察读取之前返回，
  真实远端状态检查仍由明确同步执行。空闲回执明确 `remote_checked: false`。
- 回放同步先用一次轻量远端提交探针确认仓库版本；远端版本、本地回执、
  待发布队列和本地比赛修订都未变化时，不启动远端回放读取 worker、不读取
  历史回放正文，也不重建或上传文件。
- 已发布历史分片通过对象身份复用，谱系比较只读取改变的尾块；只 stage 改变文件。
  同一上传内已通过的对象不重复校验；远端树确认全部预期对象，正文只读回根索引和改变文件。
- 相同回执、同步状态与生成缓存不重写，避免 mtime 改变制造假任务。发布最终标记
  在所有本地发布文件完成后保存，文件缺失或变化仍会恢复，不能空闲跳过。
- 卡牌已归档元数据以目录版本缓存，最多 512 张；既有磁盘与浏览器图片缓存继续复用。

这些变化减少实际工作量，没有用减少账号检查、关闭损坏恢复或遗漏发布版本来换速度。
更改时仍会遍历小型内存索引，首次启动／代码规则改变时要建立或修订缓存，
不能声称所有路径的计算量都严格只与单条变更成比例。
