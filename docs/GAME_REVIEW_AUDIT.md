# 先检查决定，再筛选点评

先从原始回放生成检查位置，逐回合比较真实可执行方案，再独立复核重要分支，最后绑定准备展示的点评。少量点评是编辑结果，不是检查数量上限。

## 实际工作流

1. 固定本次比赛的已核实来源，准备一个私有输入：`{ replay, cards, source_content_hash, game_number }`。`replay`与`cards`来自同一份已验证的发布资料。静态牌库只用来查已见牌的规则，不用来补未知手牌。
2. 运行离线工具生成检查清单。它只读取指定比赛，不启动服务、不联网、不扫描归档，也不调用模型。
3. 逐回合写检查记录。可以把同一回合相关施放、能力与攻防合并成一个整轮计划，但每个位置都要有自己的比较和证据。看手拿牌必须独立记录，每张展示牌都比较对手能否使用、自己能否使用、真实费用与兑现时机。
4. 对改变主线的分支独立复核。检查支付顺序、状态动作、触发、当前对象、下一轮攻防，以及对手改变回应后是否仍有收益。依据只限该选择时已有的信息；复盘总结另讲实际后来怎样发展。
5. 最后选择展示位置，绑定最终点评正文的哈希，再运行检查。修改正文或数据后重做相应检查。通过后才进入已有来源校验、发布、同步与页面检查流程。

```sh
node scripts/audit-game-review.mjs plan INPUT.json NEW-PLAN.json
node scripts/audit-game-review.mjs check INPUT.json LEDGER.json REPORT.json
```

清单是待检查的位置，其中包括强制目标和自动触发，不可把数量称作独立错误数或思考深度。它不列穷举合法行动，也不证明已经找到最佳打法。

## 每回合要留下什么

记录当前事实、实际行动、可执行替代线、明确倾向、原因、机会成本、对手可调整的回应，以及下一次应检查什么。对同回合合并的每个位置，另写具体比较和对应证据，防止“本轮重建场面”吞掉选目标、保留费用或错过落地。

检查范围包括自己的整轮计划、对手回合的响应或通过、手中已有地的使用、施放、启动、目标、弃牌、攻防、主阶段抽到新牌后的更新，以及看手选择结算后是否能马上转换资源。没有响应可做和合理不攻击，也留下原因；它们不需要因此变成页面上的一条点评。

`hand-choice`只从该次效果前已记录的公开展示事件收集候选。对手`hand`字段为空不表示没有看见手牌；另一方面，缺少展示事件也不能用更早的手牌或最终牌库补齐。候选数与当时手牌数不符时，内部记为未决，不能声称完整比较过，更不能为了通过检查补造候选。

检查记录中可有未决项，写清缺什么证据；其他完整且有价值的选择仍可展示。未知信息只在它实际影响判断的位置说明，页面不增加通用免责段落。

67e50c31的T17拿牌：对方五地和两本书共有七费，却只有两个红，付不出巨像的三个红；自己的八地已付唤师四费，手里海岛未落，墓地已七。拿狱火后落第九地即可当轮借用，杀五四默武再加豆。拿巨像的未来上限必须和这条本轮返场路线直接比较。

这两处都来自当时已知手牌、墓地与场面，既没有等待未知抽牌，也没有要求对手照原线路行动。分析应说明它们如何改善攻防，以及对手调整后需要怎样继续应变。

## 检查能证明什么

工具会拒绝遗漏位置、跨回合泛化合并、缺失逐位置比较、不完整看手却声称已定论、当前窗口之外的证据、旧来源记录，以及同锚点换了正文的点评。

通过表示检查记录和最终内容对应。战略比较是否准确，仍由具体推演和独立复核检验；页面测试只验证显示、定位与同步。交付时分别说明这些证据，不能把其中一类说成另一类。
