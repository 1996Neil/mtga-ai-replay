# Replay 2.0 P3：归档稳定、固定来源与同步性能

写作结构：先核对归档变化和版本，再比较来源方案，最后列性能、测试及正式集成门槛。

本候选基于 main `56abfbb`，在本地整合 PR #12 `776294c` 与已验收的 P3 补丁。没有合并 GitHub PR、部署桌面、改写真实归档或再次发布真实复盘。

## 归档变化及修复

已定位实际触发者：另一项上传计时任务部署旧版五文件补丁时，经原启动器停止旧服务、启动新服务。部署回执、五文件当前 SHA、服务 PID、55 行更新时间和自动导入状态一致。启动后自动导入执行一次，非缓存命中，写入55场。计时补丁未直接修改解析器，但全部顶层 src 模块都参与导入规则指纹，计时模块变化也会使缓存失效，重新执行当时本地已有的解析修复。

旧 `canReplace` 只检查全场聚合覆盖数不减少，同覆盖度也能覆盖，不能区分序号/名称变化、事实冲突和真正补全，跨局还可互相补偿。写入会更新 replay_json、summary_json/revision 和 updated_at；Coach Notes 单独存储。

不能把55场都归为序号变化：保存了完整前后原始副本的807动作比赛有910处 sequence 整体+3；另7场胜负变化已有另一任务的显式比赛ID、席位、终局证据，本轮复核其38条引用日志行 SHA 全部相符。50场可恢复净化后的已发布导出，结构比较未见已记录动作减少，总动作16299→16309；这不能证明原始SQLite逐字段等价。另5场缺少同等旧副本。本轮不回滚任何真实结果。

实现采用保守准入：逐 game_number、重叠事实和时间线前缀检查；拒绝同覆盖度变化、名称/sequence/已知结果变化、已知生命值改变、缩手牌、删局、重复局号及跨局补偿。只有保持已知事实不变、确实增加覆盖或补齐未知结果的窄范围候选可更新，并返回冲突数。复杂残片补全（空起手变有牌、缺失终局警告消失、事件重排等）仍需人工审查，不声称自动支持所有 partial→complete。

新解析 sequence 按比赛计数，前置其他比赛增删不再影响本场。整合本地已有的纯 `match-metadata.mjs` 修复及合成反例：显式 matchID 优先，已关闭比赛后的下一场 ConnectResp 不再污染前场席位，强证据冲突保持未知，Bo3单局结束不误判整场结束。缺 matchID、缺终局时多个弱 ConnectResp 的歧义仍未全面解决，不据此迁移历史。

机器名称与展示分开：名称和计数器读取拒绝中文补丁标签，尝试英文变体，无可用值时保留 Arena ID/Counter 编号。字符过滤不等于官方译名验证，也不猜译名。中文只在展示层添加，英文身份与 V2 Schema 不变。

## 长期绑定方案

| 方案 | 正确性及维护边界 | 结论 |
|---|---|---|
| 固定提交的历史发布源只读回放 | 精确读取并重验 manifest、parts、cards、report；不依赖当前SQLite或本机译名；单独目录、不可变会话、明确来源 | 已实现，作为长期入口 |
| 严格兼容副本 | 仅人工审计过的别名、计数器和一致偏移；最终完整hash仍必须精确相等；扩展规则增加审查成本 | 保留显式工具，不接入自动reader |

新增 `node bin/mtga-replay-history.mjs --match <id> --game 1 --revision <完整commit>`。必须显式给完整提交号，只接受完整安全扫描后默认分支的祖先；不抓任意孤立对象。每次打开重新核查 PRIVATE 和全历史，单独目录与普通 review 缓存分离；不调用本地比赛loader、不写归档、不启动日志观察、不提供上传或更新动作。

Worker在自身上下文创建来源能力，验证全部文件hash、隐私、局数、动作/状态数、锚点及 before/after，主线程接收后分段深冻结。界面标明“历史发布源 · commit · 只读（独立于本地归档）”。卡片名称和规则来自固定字典，未知ID拒绝；已有本机图片仅供展示，禁止在线规则覆盖。

普通本地reader的完整bundle hash、输入指纹、远端失效与独立回执检查全部保留。显式查看旧来源不会给当前本地不同内容的比赛加上 ready 标记。

## 同步归因与结果

同一完整历史：220提交、1043树、4185历史blob、共2276033769字节blob。每轮重读原始Git对象并验证hash，语义复用数为0。耗时主要在历史语义扫描，不能归因于网络下载或分片读取。

最小优化：紧凑worker字节拷贝；按2MiB阈值合批、最多两批并行；同路径不同历史版本先flush，避免Map覆盖。2MiB是合批阈值，单个大历史文件仍完整检查。失败时等待已发任务结束并清空安全会话结论。单文件 positive-only 有界 memo 只复用已经通过的完整 key+类型和短字符串；完整原始JSON、重复成员、转义、路径、隐私与原始文本仍检查，无跨文件或跨调用 verdict。decoded 与 text 相同时去掉同一文本的第二次重复扫描。分片改为有界Git批量读取，长度、framing、对象hash及EOF继续重验。

HTTP输出修复前的完整历史会话测得 **57.272秒**：PRIVATE 1.756s、fetch 3.989s、历史扫描44.747s、文件0.424s、来源验证5.987s、冻结0.189s；峰值RSS **876.34MiB**，事件循环最长 **203.03ms**。初次紧凑拷贝实验主要降低内存，并未明显降低CPU，保留实验记录。并行后的 semantic_ms 是任务累计等待时间，不能当独占CPU或与墙钟相加。

网络和后台负载有波动；这些样本不是五轮严格A/B，旧约225秒也不作为受控基线。30秒首次同步及100ms最长停顿仍未达到。203ms尾值单独保留，尚不能归因于单一环节，没有因此放宽检查或大规模重构。HTTP探针只使用真实健康路由，结果单列。

HTTP额外验收发现历史JSON约50MB，主线程序列化造成健康响应最长1594.57ms（25次均200）。已将历史会话的序列化/UTF-8编码移到短生命周期worker，独占输出buffer转移至主线程；每次请求复制保护私有快照，普通本地输出路径不变。修复后同一约50MB响应58.59ms；24次health全部200，最大25.35ms、P95 12.85ms。此证据只证明服务端响应，浏览器解析/渲染不能由此推定。旧失败证据保留。

含最终HTTP修复的完整打开另测 **92.842秒**：PRIVATE3.325s、fetch5.333s、历史扫描76.834s、文件0.488s、来源验证6.489s、冻结0.191s；峰值RSS **1153.48MiB**，事件循环最长 **212.07ms**。扫描代码与较快轮次一致，运行环境有其他任务，差异未做严格受控归因，不以57秒替代最终结果。

## 正式集成门槛

main 已包含PR11界面，PR12仍独立且不是main祖先；本分支只在本地整合P2祖先链。保留既有浮窗、Schema、发布器和内存释放。

当前桌面使用旧目录的 `launch.mjs → launcher.mjs → live-coach serve --standby --mode replay`。它是含多项dirty修改的旧项目，不能等同main或PR12；启动器一致，server/history/replay/cards/uploader/security已分叉，另有上述五文件计时补丁。本轮保存逐模块SHA与部署清单，不用单一commit冒充实际代码版本。

**实际正式上传校验器在隔离真实Git副本上拒绝 reviews 路径。** 这是旧版未支持时的安全拒绝，不能称正式上传已兼容。候选完整扫描接受合法 reviews；裸仓库测试验证 Agent 写入后比赛上传仍正常、保留 review 字节，review不能进入比赛/收藏发布命名空间，恶意其他分支仍阻止操作。没有在真实数据仓库试传。

不得用本分支直接覆盖正式dirty目录；正式目录的轮抽/计时等未提交功能仍须另行核对。获得明确部署授权后才可备份、选择入口、切换和验收。当前交付是独立源码 Draft。
