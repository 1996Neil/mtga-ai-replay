# 本机同步代理

桌面启动器不一定继承采集LaunchAgent的环境，导致后台能上传、页面“同步回放”
却在远端阶段连接失败。本轮把所需代理设置统一到私有数据目录的 `sync-network.json`。

```sh
node bin/mtga-sync-network.mjs --https-proxy http://127.0.0.1:PORT
```

仅接受带明确端口、无用户名密码的本机HTTP代理（127.0.0.1、localhost、::1）。
配置通过已有原子写入保存为600权限，不进入源码／数据备份仓库；
拒绝符号链接、非私有权限、未知字段和超大文件。系统代理、游戏和进程环境不改写。
已有显式HTTPS_PROXY／ALL_PROXY环境设置优先。

共享Git/GitHub执行器在一次同步操作中懒加载一次配置，仅传给其子进程。
所以桌面同步、采集上传和教练复盘同步使用同一设置；没有后台探测、额外轮询或新依赖。
子进程专有设置（固定Git身份／目录等）保留，网络错误仍去除命令输出中的敏感信息。
更改配置后新同步操作生效；长驻服务重载后使用更新的执行器。

测试覆盖合法本机代理、外部地址、凭据、路径／查询参数、文件权限、符号链接、
既有环境优先及子进程环境保留。真实应用复用原采集服务已经配置的本机代理端点。

## 独立上传后的旧回执

单独更新某场回放后，完整内容可能已在远端但下载回执仍指向旧版。
此前普通同步会把这种情况当成双边冲突。现在仅对实际冲突候选读取并严格核实
远端manifest／全部分块，以本机回放加已验证远端卡牌资料、相同历史路径及分块模式
重建全文哈希。全文完全相等且本地版本未变化才补回执，不覆盖归档、不重复上传。
全文不同或核验期间版本变化仍报告冲突。该分支不参与空闲同步和轮抽语义关联检查。

针对性临时Git测试验证旧回执可自动对齐、下载／上传均为0、本地归档不变，
并验证真正双边修改仍保留双方、拒绝覆盖。没有放宽远端哈希、权限或来源校验。

## 实际验证

页面原失败停在远端阶段约32秒；配置本机服务已有代理后能正常连通。
随后定位到一场单独上传后的旧回执，按全文一致性核对成功恢复，真实不同内容的
临时Git回归仍拒绝覆盖。页面实际完成35场更新与3场新增，关联补发失败后单独重试成功；
最终页面再同步状态为 `succeeded`，没有新增、更新、下载或失败，
本地／远端比赛均234场。独立复核未发现阻塞问题。
原本未完成的网络请求没有被当作成功，未执行强推、全量重建或系统代理修改。
