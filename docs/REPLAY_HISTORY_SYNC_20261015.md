# 轮抽记录与同步修复

## 行为

轮抽已结束、结算负场为 3、三场归档均为负、没有归档胜场且结算胜场字段缺失时，按用户指定的显示规则呈现“已结束 · 0胜3负”，不再显示胜场未知提示。这是展示默认值；原始胜场仍为 null，内部 score_verified 仍为 false，不回写推定数据。有胜场、未知结果、归档不足三场、未结束或其他计数冲突时，仍显示原有核对提示。

记录日期显示两位年份，活动名隐藏末尾日期后缀；列表采用上行日期与活动、下行左侧状态和右侧颜色与胜负。卡组颜色按最后一场归档主牌组的地牌归类，混血法术不扩充颜色。宽度相对此前列表缩小五分之一。

正在回放的比赛在轮抽分组和“全部比赛”中同步显示选中底色、左侧标记与“正在回放”。状态绑定已成功加载的比赛，切换后旧项取消；切换账号会清除原选择，进入选牌页时不标记旧对战。选中背景与鼠标悬停有区别，辅助技术通过 aria-current 读取当前项。

## 源码基线

此增量基于云端复盘 P1 的 bf70d79。该基线尚无本机正在使用的轮抽功能，因此定向带入必要的索引、逐手记录、HTTP 只读接口、适配及类型，同时保留云端复盘、旧 Notes、compute pool、上传回执、提交归属与历史安全检查。没有合并其他 PR，也没有带入语音或其他棋盘布局工作。

## 完整性修复

- 比赛座位索引以明确的比赛 ID 和终局边界绑定，下一场 ConnectResp 不再覆盖上一场结果；单局结束不等同于多局比赛结束。
- 部分轮转日志更新后，读取时根据全部保留的 linked members 重新统计战绩及核验状态，不改写历史行。
- 导入缓存涵盖轮抽 sidecar 及 WAL，索引变化、删除或恢复会使旧回执失效；空 WAL 不视为数据变化。
- catalog 在读远端索引、生成及入队前完成完整历史检查，包括没有候选的 warm 同步；发布前精确 SHA 检查保留。
- 推送失败保留 pending 及未确认状态；collection 回归保留与比赛上传器的 namespace 隔离和错误去敏检查。

## 2026年11月1日：轮抽分组可见性

比赛菜单与选牌回看分别筛选：有归档对战的赛事组即使没有逐手选牌，也保留在“轮抽记录”；只有选牌回看要求有效选牌。没有选牌的组不显示空的回看入口。

已有发布关联仍保留，但不阻止本地新赛事和同赛事新增场次进入记录。新增成员必须通过赛事上下文、主牌与账号核对，唯一性同时考虑保存的旧牌池与近期日志，避免日志轮转后误连。已发布成员与选牌不被局部资料替换；无法加入原关联的剩余场次仍保留为赛事对战组。

读取沿用现有revisionMemo与赛事元数据缓存，无变化请求不重建，也不新增模型调用、上传、定时任务或原始比赛写入。26项相关后端检查及8项选牌展示检查通过，类型检查与构建通过；实际桌面19项检查确认两个账号隔离、日期与分组、场次、点击回放和选中标记。10月30日两组13场均在，最新轮抽9场也恢复进入分组。本机服务已更新。

## 2026年11月1日：比赛同步等待共享通道

比赛同步在读取远端索引、入队、上传和轮抽关联发布阶段，显式等待另一个活跃同步任务释放共享锁。等待保持同一任务为running，页面显示“等待其他同步完成…”，浏览器关闭或重开仍按原流程观察服务端任务。默认最多等五分钟，等待只检查锁，不重新扫描比赛或发起远端请求。

取得锁后每个回调只执行一次；等待不包裹上传回调，不重试已产生提交或结果未知的推送。过期锁、无效锁和显式恢复闸门继续要求原有核对，不能删除其他进程的锁。没有选择等待的旧调用仍立即返回占用。

轮抽发布工作进程仅转发等待、比较和远端查询阶段；这些属于显示进度，不当作完成结果，也不替代提交检查点。一次进度显示异常不终止或重标正在进行的发布，最终结果继续使用原有回执与任务日志保存。

34项后端相关检查及5项同步展示检查通过，类型检查与构建通过，独立审查未发现阻塞。本机实际页面只启动一个任务，等待后台备份约九秒后自动继续；此前未上传的五场全部上传成功，失败零场，远端和轮抽关联回执均已核对。
