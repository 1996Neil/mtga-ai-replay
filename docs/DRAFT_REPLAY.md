# 轮抽选牌回看

2026-10-30。本次按“开源方案核验 → 现有数据接入 → 界面与验证”的顺序记录。

## 接入结果

Replay 顶部的「轮抽」入口显示候选包卡图、实际选择、按包和手的导航、进度滑块、
截至当前手（含本手）的已选牌，以及点击放大的卡牌。比赛记录里的每场轮抽也有「打开选牌回看」入口。
合并不同采集来源后，按实际时间从新到旧排列；没有有效逐手记录的场次不显示，
默认打开最新的有记录轮抽。过滤只影响显示，保存的数据和全部比赛不删除。
轮抽记录统一使用左侧列表。
上一手／下一手与包、手进度位于右侧，滚动候选包时保持可见。
候选包下方按费用从左到右显示已选牌，采用构筑对比的纵向叠牌：
保留上方牌名、插画与类别行，仅遮挡下方规则文字；重复牌标注张数，费用未知列放最后。
费用使用当前牌图元数据，冒险／备战等双费用使用印刷正面；不新增接口、轮询或后台计算。
移除旧的侧栏「当时的牌池」和选前／选后开关，切手时已选牌直接使用该手 `pool_after`，
向前回看不展示后续选到的牌。
系统仅维护桌面布局；切手控制始终位于右侧，不再提供手机底部切手栏。
轮抽视图使用 `?view=draft`，刷新页面后仍可直接进入。
左侧「轮抽记录」支持收起／展开。桌面收起为窄入口，让出候选牌空间；
状态只保存在当前浏览器，刷新或切换账号后沿用，
不改变当前选中的轮抽或抓位；浏览器存储不可用时仍能正常切换。
已选牌使用暗色薄边和紧贴的接触阴影表达叠放厚度，静止时不旋转、不缩放，
不叠加亮边；悬停仅上移 3px，保留下一张插画可见。桌面范围及参考见 `DESKTOP_UI.md`。

只读取现有 `/api/draft-runs?account=…`，复用卡图接口和中文显示名；不引入依赖，
不更改采集、数据库、账号归属、私有 Git 备份或模型调用。
仅记录了轮抽而没有比赛时，也可进入回看。

### 数据边界

- 导航只遍历已记录的手；编号间断、缺少候选包、来源冲突、缺少选择都提示，不补造选牌。
- 牌池直接取当前手的 `pool_before` / `pool_after`；相同 Arena ID 按张数合并显示。
- `complete: false` 时明确提示记录不完整。17Lands 采集来源保留分段和比赛关联待核验说明。
- 旧采集格式即使将后续某手标为完整，界面仍检查之前的缺失和编号间断，保留牌池不完整提示。
- 实际选择不在候选包中时单独展示，不插入候选包；重复 ID 只标记第一个匹配，
  因为现有数据没有相同卡牌副本的选择位置。
- 每三秒刷新沿用既有循环；已选手使用包／手身份保持位置，新记录不会自动跳走。
- 左右键浏览，Home / End 跳到首尾；输入框、下拉框、修饰键和卡牌弹窗保留原有键盘行为。
- 当前实现是历史回看，不向 Arena 提交选牌，也没有接入 17Lands 评分或模拟其他玩家。

### 牌图缓存

既有磁盘缓存位于数据目录的 `cards/<Arena ID>.jpg`（旁边保存 JSON 元数据）。
已缓存图片由本机读取，不会每次重新访问 Scryfall。
此前所有接口统一发送 `Cache-Control: no-store`，浏览器无法复用图片，
且候选卡组件的 key 含当前手编号，切手必定销毁重建卡图。

现在成功返回的公开卡图使用 `Cache-Control: private, max-age=86400`，
允许浏览器缓存一天；元数据、私人回放、错误响应仍为 `no-store`，
显式 `?retry=1` 恢复图片也不缓存。相邻手中保留的候选牌使用稳定身份，
不因手编号或其他候选的移除而重建。重复牌仍以出现次序区分。
未见过的图片首次显示仍需加载，尚未缓存的卡图仍受既有下载队列与重试规则约束。
