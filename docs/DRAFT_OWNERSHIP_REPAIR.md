# 轮抽账号源头修复

实现范围：修复17Lands适配器跨Arena日志重置继承旧账号的问题，并为明确选择、
已经核实完整牌池与当前对战身份的历史轮抽发布账号纠正。不是全量重采、账号猜测
或比赛重建，不修改原始日志、采集数据库中的记录或既有不可变备份块。

## 根因与源头行为

17Lands的 `Updating user info` 可能到第一场对战开始才出现，不能假设它早于选牌。
过去只处理跟踪器启动、登出、重连，漏掉了Arena日志的
`Starting from beginning of file…`。现在收到该提示立即清除活动及待恢复账号，
无明确身份的选牌保留本地，不继承上一账号，也不根据随后登录的账号倒推归属。
正常日志轮换仍保留游标和已确认身份。

## 定向历史纠正

先预览，确认后写入本机小型纠正账本：

```sh
node bin/mtga-draft-ownership-repair.mjs --run <run-id> --run <another-run-id>
node bin/mtga-draft-ownership-repair.mjs --run <run-id> --run <another-run-id> --apply
node bin/mtga-draft-sync.mjs
```

只能选择已经发布、完整牌池精确匹配、所有已关联对战账号一致、当前本地对战版本
仍与发布证明一致的账号冲突记录。CLI不接受任意目标账号，目标来自已核实的对战。
输入已过期、比赛缺失或来源变化会拒绝修复。重复执行不重复写入。

账本位于数据目录 `draft-sync/ownership-corrections.json`，只保存源账号哈希、
正确账号哈希和精确的采集分段指纹。使用既有同步互斥锁、私有目录及原子写入；
限制结构、大小和重复来源，拒绝符号链接。

备份的原始账号目录与观察字节不变。发布器在现有 `bindings.json` 的已关联行
加入可选 `ownership`，只允许 `verified_pool_and_match_identity` 方法，
正确账号必须与该行所有对战一致，来源分段和内容指纹必须与授权账本完全一致。
完成既有远端对象核对和正文回读后，Viewer才按纠正账号分类。
来源账号保留为 `capture_account_key`；归档对战账号和其他账号的数据不改写。
纠正信息随关联资料备份；证据持续有效时，恢复或重试会保留已发布纠正，
不依赖本机账本仍存在。本机账本应保留：如果账本已丢失且中途又发布一次待关联状态，
之后证据恢复时需要重新执行定向纠正，不能从已经失效的关系自动推断新授权。
没有对应当前对战证据时恢复为待关联，不把旧纠正当成新的身份依据。

关联协议保持V1且新增可选字段；旧阅读器会拒绝未知字段，部署前需更新正在运行
的本地服务。输入变化进入既有增量信号；空闲轮询不读取账本正文、不扫描比赛。

## 验证边界

针对性测试覆盖日志重置后延迟身份、重连不能恢复旧身份、初始化／重启、
正常轮换、原子事务、断尾、损坏输入；以及纠正授权、来源指纹变化、
混合／未知账号、非法账本、符号链接、幂等计划。
临时Git远端测试覆盖纠正发布及回读、原始块不变、无本地账本恢复／重试、
错误目标账号拒绝和当前对战证据缺失。测试不访问真实远端或原始用户日志。
