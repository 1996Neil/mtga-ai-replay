# 轮抽 AI 复盘

实现范围：在轮抽回看增加 AI 复盘入口、带语义颜色与符号的抓位框、当前抓位评论和上一条／下一条评论导航。沿用对战的复盘配色与浮窗样式，不改变原始选牌、赛事关联、对战复盘或同步任务。

验收：已有真实选牌评论可读取；有评论和无评论的抓位可区分；点击评论定位正确补充包／抓次与选择前牌池；同名分段、切换账号、旧请求和数据变化不会展示别场评论；缺失或损坏的报告明确显示状态。验证采用针对性测试、类型与构建检查，以及真实浏览器操作。

## 本地读取契约

`GET /api/draft-runs/<32位run_id>/review?account=<64位账号key>` 只读取当前账号可见的真实选牌分段。返回 `ready`、`missing`、`stale` 或 `error`，非 ready 不附带评论。未知或不属于所选账号的分段返回 404。只读历史比赛视图不读取本机选牌报告。

报告保存在数据目录的 `draft-reviews/<account_key>/<run_id>.json`。采用 `MTGA_DRAFT_AI_REVIEW_V1`，包含账号、分段、事件名、选牌内容指纹、生成时间、总结和按包／抓次标记的评论。评论的重要性、判断性质和置信度与对战 V2 相同。

指纹覆盖按包／抓次排序的候选卡 ID、实际选择 ID、选择前后牌池与完整性；名字和轮询时新建的对象不改变身份。显示前重新核对整份指纹、每个评论的实际选择与备选是否在同包。记录变化时旧评论失效，不自动替换哈希。

文件大小最多 256 KiB，读取不跟随报告目录和文件的符号链接。报告文本按普通 React 文本显示，不解释 HTML 或其中的指令。没有新增浏览器写入接口、模型请求、网络上传或数据库迁移。

## 评论显示

沿用对战的 `reviewPresentation`：绿色加 ✓ 表示值得保留，蓝色加 i 表示一般策略建议，橙色加 ◆ 表示重要／关键建议。颜色不代表错误已经被证实。当前选中抓位另外显示外框；评论颜色仍保留。没有评论的抓位维持原样，不代表该选择正确。

报告按需读取，切换抓位不重复读取整份报告；切换账号或分段立即撤下旧评论。轮询新增记录改变指纹后重新核对。没有评论时入口仍可打开，说明暂无复盘并提供重新检查。

按2026年10月31日的用户反馈，评论正文只显示具体判断与卡牌比较。移除重复的观察、通用评价规则、置信度、免责声明、底部提示和“分析边界”区块。来源绑定仍由后台校验。

加载报告、切换轮抽、上下手按钮、键盘与进度条都不自动打开或展开评论窗。窗口已打开时，内容可随当前抓位更新；折叠或关闭状态保持。只有用户主动点顶部复盘入口，或复盘内的上一条／下一条评论导航，才打开或展开窗口。

评论写作区分抓位阶段：前几抓优先单卡质量与灵活性，不把最终曲线倒推成早期必须补低费。建议需给出具体选择，并用双方牌文、费用、适用局面和当前实际配合说明差异。未知信息只在影响这手选择时具体指出，不追加每条通用免责语。

## 已有报告的导入

本地 CLI `bin/mtga-draft-review-import.mjs --report <分析JSON> --evidence <原始序列JSON>` 将本次已有选牌分析转换为 V1。先核对原始序列摘要，再核对所有允许分段、账号以及当前完整选牌指纹。不同账号的分段不挪动归属，不用相似牌池或时间推断关系。写入采用同目录临时文件、完整写入并同步，再通过硬链接原子安装；已存在的不同报告会拒绝覆盖。重复导入相同内容不改变文件。
